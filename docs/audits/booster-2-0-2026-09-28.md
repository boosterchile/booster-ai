# Revisión Booster 2.0 — 2026-09-28

**Fecha de medición**: 2026-09-28
**Qué es**: el producto anterior a este repo. Proyecto GCP `big-cabinet-482101-s3` («Booster by TVO», creado 2025-12-23), más la API key Gemini del proyecto `gen-lang-client-0486421631` («Booster 1.0»). Mismo billing `019461-C73CDE-DCE377`.
**Stack que ADR-001 reemplazó**: Express + Prisma + npm workspaces + Python FastAPI. El código hermano vivía fuera de este repo (`Booster-2.0/`). En esta máquina ese checkout no está.
**Dólar usado en la revisión de costos**: 964 CLP/USD (dólar observado 2026-09-28).

Esta sesión no tiene `gcloud` ni ADC de `booster-ai-494222`. No se listaron Cloud Run, Cloud SQL ni el billing export. Lo que sigue es la superficie pública medida hoy, el inventario del 2026-05-13 y lo que este repo todavía dice.

## Conclusión

La cara pública de Booster 2.0 ya no existe. `boosterchile.com` resuelve en Cloud DNS y sirve Booster AI. Los hosts de rol (`driver`, `fleet`, `shipper`, `admin`, `fms`) no resuelven. Firebase Hosting del proyecto legacy responde «Site Not Found».

El proyecto GCP no se borra en esta sesión. El 404 de Firebase usa el mismo cuerpo que un sitio de un proyecto que no existe, así que no prueba el `projects delete`. La última medición de recursos y tráfico es del 2026-05-13 (USD 80–150/mes, 259.184 requests en 30 días a `booster-backend` en `us-central1`). Esa cifra ya no describe el producto que ve un usuario: el dominio no manda tráfico ahí. Si el proyecto sigue vinculado, Cloud SQL `booster2-db-new` y los Cloud Run con mínimo > 0 son gasto sin audiencia. El corte es confirmar costo y requests de 30 días en Costos → por proyecto y, si están en cero de uso, borrar los dos proyectos. Si el desglose ya muestra cero desde junio, el ahorro de mayo ya está en la factura y no hay nada que cortar.

Fuera de GCP queda un sitio GoDaddy («Próximo lanzamiento», copyright 2025) en las IP viejas de AWS Global Accelerator. El DNS público no lo usa. El certificado HTTPS venció el 2026-05-16. Si GoDaddy Website Builder sigue contratado, se cancela en esa consola, no en Terraform.

Fuente: `docs/handoff/2026-05-13-cross-projects-audit.md`. Ese día el proyecto estaba linked al billing y tenía:

- Cloud Run: `booster-api` (us-central1), `booster-backend` (southamerica-west1 y us-central1), `booster-fms-python` (saw1), `booster-frontend` más admin/driver/fleet, `booster-landing` (us-central1), `booster-worker` (saw1).

- Buckets de Cloud Build, frontend, documentos y fuentes de Cloud Run.
- BigQuery `booster_cloudrun_logs`, `booster_iot`, `booster_telemetry` (`gemini_requests`, `sensor_readings`).

Tráfico 30 días de ese corte: `booster-backend@us-central1` 259.184, `booster-landing` 39.474, `booster-backend@southamerica-west1` 503, el resto bajo 20. ## Qué cortar, y qué no

| Pieza | Decisión | Motivo |
|---|---|---|
| Proyecto `big-cabinet-482101-s3` | No se borra desde aquí | Sin lectura del billing no se distingue «ya borrado», «sigue pagando SQL y Cloud Run» y «alguien todavía pega a `*.run.app`». `gcloud projects delete` es irreversible y ADR-076 pide lista de verificación. El PO lo confirma en Costos → por proyecto, 30 días |
| `gen-lang-client-0486421631` | Igual | En mayo era USD 0–5 y una key sin tope. ADR-055 todavía lo veía el 2026-06-03. Misma fila del dashboard |
| DNS, LB y la PWA de `boosterchile.com` | Se quedan | Son Booster AI. Revertir apex/www a las IP de AWS volvería a publicar el sitio «Próximo lanzamiento» |
| Sitio GoDaddy en `13.248.243.5` / `76.223.105.230` | Cancelar en GoDaddy si la suscripción sigue activa | No está en el DNS. El certificado venció el 2026-05-16. No es un recurso de este Terraform |
| Datos de BigQuery `sensor_readings` / `gemini_requests` | Exportar antes de un delete, si el dataset sigue ahí | Es la historia de telemetría y de uso de Gemini del producto viejo. Borrar el proyecto se las lleva |

Si el desglose de 30 días muestra costo > 0 y los requests no son de un cliente (el dominio ya no llega), el orden de corte es: export de lo que haya que conservar, `gcloud projects delete big-cabinet-482101-s3`, después el proyecto Gemini si su costo es solo la key legacy. El ahorro, si el proyecto sigue vivo con el piso de mayo, es USD 80–150/mes (CLP 77.000–145.000) más USD 0–5 del proyecto Gemini.

## Cómo cerrarlo en el dashboard

1. Platform Admin → Observabilidad → Costos → por proyecto, últimos 30 días.
2. Anotar el neto de `big-cabinet-482101-s3` y de `gen-lang-client-0486421631`.
3. Cero en ambos: el sunset ya está en la factura. No hay delete pendiente. Queda mirar GoDaddy.
4. Costo > 0: en Cloud Monitoring del proyecto, requests de 30 días de `booster-backend` y CPU de `booster2-db-new`. Sin requests de usuarios, agendar el delete con export previo. Con requests reales, identificar quién pega a la URL `*.run.app` antes de apagar.
